## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Устаревшие сгенерированные моки не соответствуют интерфейсам, а тест очистки кеша зависит от планировщика. Это блокирует проверку исправлений отказоустойчивости.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Общий go test всех пяти модулей проходит
- [x] #2 Проверки кеша проходят с race detector и не зависят от коротких sleep
- [x] #3 Моки соответствуют актуальным интерфейсам; прежнее удаление tasks/run сброшено по явному разрешению пользователя
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Сгенерировать моки только для пакетов с устаревшими интерфейсами, исключив удалённый tasks/run. 2. Обновить фикстуры refresh для текущего поведения. 3. Заменить проверки с короткими sleep на явное истечение времени и синхронизированные проверки. 4. Выполнить общий go test и race-проверку кеша.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Общий go test пяти модулей проходит; go test -race ./pkg/cache проходит. Перегенерированы шесть устаревших mockery-файлов. Фикстуры refresh проверяют текущую очистку сессий. Проверка кеша больше не содержит требования уложить миллион операций в одну секунду: это нагрузочное измерение, не функциональный контракт. Пользовательское staged deletion tasks/run/mocks_test.go сохранено.

После явного разрешения пользователя старые изменения auth/refresh, PostgreSQL refresh tokens, Docker runner и staged deletion tasks/run сброшены. Мок tasks/run восстановлен и перегенерирован под текущие интерфейсы; очистка refresh-сессий и связанные с ней ожидания убраны. Сохранена коррекция fingerprint фикстуры просроченного токена, чтобы тест проверял истечение срока вместо компрометации.

Повторный общий go test пяти модулей после сброса проходит, включая PostgreSQL integration на собственных временных БД.
<!-- SECTION:NOTES:END -->
