# Владение PostgreSQL pool и транзакциями

`poolx.New` создаёт pgx pool и передаёт его приватному этапу проверки соединения.
Если Ping завершается ошибкой, pool закрывается. После успеха владельцем становится
возвращённый клиент; вызывающий код закрывает его через Close.
Узкий Postgres-интерфейс находится внутри shared-адаптера и позволяет проверять
владение ресурсом без сетевого I/O в unit-тесте. Типы pgx не выходят в usecase-ы.

Context хранит транзакцию под ключом с указателем на конкретный Poolx. Операции A
используют транзакцию A, даже если между ними открыта транзакция B. Клиент B без
своей транзакции работает через собственный pool. Повторный InTransaction того же
клиента в активном transaction context возвращает ErrInvalidArgument до Begin;
вложенные savepoint-транзакции этим API не поддерживаются.

Транзакции разных клиентов независимы: commit B остаётся после rollback A.
Это не распределённая атомарность. Transaction context нельзя сохранять для
использования после выхода callback или передавать конкурентным операциям одной tx.

После Begin сразу установлен defer Rollback. Ошибки rollback добавляются через
errors.Join к ошибке callback/commit; logger в context не требуется. Исходная panic
callback распространяется после попытки rollback. Отмена и timeout не отключаются;
WithoutCancel не используется. Интеграционный тест проверяет отмену, отсутствие
записи и повторное использование того же ключа в следующей транзакции.

Unit-тесты проверяют ошибку Ping, передачу владения, вложенность, panic и сочетание
ошибок callback/commit с rollback. PostgreSQL-интеграции включаются через
PINN_TEST_POSTGRES_DSN и создают собственные временные БД без миграций рабочих данных.
