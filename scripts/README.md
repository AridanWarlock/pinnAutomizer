# Проверки качества

Требуются Go из go.mod и make. Runner собирается в `.tools/quality` из
`pkg/cmd/quality` штатным Go; Python и сторонние Go-библиотеки не нужны. Линтер устанавливается в игнорируемую
`.tools/` из официального release с проверкой SHA256; версия закреплена в
`pkg/cmd/quality/install.go`, системные зависимости и Go-модули проекта не изменяются.

```sh
make tools-install
make fmt
make check
make test TEST_ARGS='-run TestName ./path/to/package'
make test-race
```

Импорты: стандартная библиотека, сторонние зависимости, пакеты проекта.
Форматирование задают gofmt/gci. Линтер проверяет корректность через govet,
ineffassign, staticcheck SA* и unused. Подсказки о переписывании стиля и миграции
deprecated API не включены; расширение набора правил требует осмысленной причины.
Сгенерированные файлы не редактируются форматтером: для них используется генератор.

Проверки не читают .env. Для клона без локального go.work runner создаёт workspace
пяти модулей в игнорируемом out/quality/. При успехе выводится только итог; при
ошибке — максимум 20 строк и путь полного лога. Ненулевой exit code сохраняется.
Успешный тестовый лог вообще не разбирается. Не использовать pipe в head для
замены runner-а: это может скрыть exit code go test.

Без PINN_TEST_POSTGRES_DSN тесты БД пропускаются с явным сообщением. DSN нужно
задавать только для одноразового PostgreSQL-кластера с CREATE DATABASE permission
(см. services/tasks/README.md). GitHub Actions запускает make check с такой БД;
при ошибке полный лог сохраняется как artifact quality-logs.

Самопроверки runner-а — обычные Go-тесты, входят в общий запуск make check: настоящие успешные/упавшие Go-тесты,
ошибка компиляции, ограничение вывода и workspace без локального go.work.
